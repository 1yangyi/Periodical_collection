# 期刊投稿格式文件采集需求

## 1. 目标

每次输入一个期刊及其官网，自动查找并保存公开可访问、与稿件提交格式有关的原始文件和网页。批量运行时，逐条处理 Excel 中的期刊记录，沿用同一套单刊流程。

本阶段交付原件、来源和采集记录。字体、字号、Word 样式、PDF 正文和扫描件的解析放到后续阶段。

## 2. 收录范围

| 资料 | 收录条件 |
| --- | --- |
| 投稿须知、作者指南、撰稿规范 | 涉及稿件结构、文件格式、匿名方式、字数、排版或引用格式 |
| 稿件模板和格式示例 | 包括 Word、PDF、LaTeX 和压缩包等官网发布的格式材料 |
| 专题、语种和稿件类型的单独规范 | 保留适用范围及发布日期。链接多个版本时分别记录 |
| 格式补充通知及表单 | 与稿件格式或提交文件要求直接相关时收录。注明适用阶段 |
| 仅以网页发布的规范 | 复制网页正文，保存为「期刊名投稿格式.md」，并保留官方 URL 和网页快照 |

过刊正文、网站新闻和编辑流程表通常不在范围内。用途不明确的附件先登记为待核验。归类使用文件名、链接文字、周围说明和来源栏目。

## 3. 单刊采集流程

1. 从 Excel 读取期刊名、journal_id 和官网。保存原始网址、跳转后网址和访问时间。
2. 通过 requests 获取公开 HTML，用 Beautiful Soup 提取菜单和链接。优先查看投稿须知、作者指南、投稿格式和下载中心，继续检查相关公告、专题征稿和官网指向的投稿平台。
3. 把线索加入待查队列，记录来源页面和链接上下文。检查所有相关栏目及其可见分页。发现第一份模板后继续搜索其余入口。设置可配置的访问上限，保留未检查的线索。
4. 处理动态入口。已知该操作哪个菜单或按钮时，用 Playwright 执行。能读取页面链接但相关性难判断时，可选用 AI 排序。已检查常见入口但仍有线索需要通过浏览器探索时，调用 Browser Use。
5. 下载候选原件，检查响应类型和文件特征，避免把登录页或错误页保存为附件。对相同内容按哈希去重，同时保留所有来源链接。投稿须知等页面直接展示格式要求且未提供相关附件时，复制页面正文，保存为「期刊名投稿格式.md」，例如「财经法学投稿格式.md」。保留原文、标题、列表和表格，去掉菜单和页脚，并在文件中记录来源 URL 和采集日期。另保留网页快照，供核对。
6. 输出文件目录和清单。每条资料记录标题、适用范围、发现路径、来源页、下载地址、本地路径和采集状态。访问失败、需要登录、超出搜索上限或无法判断用途时，留下复核记录。

## 4. Browser Use 调用约定

输入包括期刊名、已核实的官网及官方关联入口、已检查页面、已发现资料和仍待查找的线索。代理在公开页面中查找，如展开菜单、查看分页或打开相关通知。返回候选资料的名称、来源页面、可复查的点击路径及附件地址。流水线验证和保存原件。如果下载依赖浏览器会话，用浏览器接收文件，再走相同的验证流程。

一轮搜索的结束条件是配置范围内的相关入口已经检查，或者记录了每个未检查入口的原因。清单报告这次实际覆盖范围。

## 5. 单刊完成状态

如果单刊结果中没有任何已成功下载、通过文件类型验证且与投稿格式相关的 `.doc`、`.docx` 或 `.pdf` 原件，则将该期刊列入 `uncompleted`。只有网页正文副本或 HTML 快照、仅发现下载链接或附件下载失败时，均适用此规则。保留已采集的资料及缺少原件的原因，供后续补查。

有效附件是完成的必要条件。已有一份有效附件时，仍应按既定范围继续检查相关入口，并记录未核查的线索。

## 6. 验收案例

| 场景 | 预期结果 |
| --- | --- |
| 多个官方入口提供同一个 Word 文件 | 只保存一份原件，来源清单保留每个下载地址 |
| 官网直接展示投稿格式，未提供附件 | 保存正文为「期刊名投稿格式.md」，记录来源；该期刊状态为 `uncompleted` |
| 已找到附件入口，但下载失败或返回错误页 | 保留来源和失败记录；若无其他有效原件，状态为 `uncompleted` |
| 找到有效附件，但仍有已知栏目待核查 | 保存原件并记录待查栏目，按采集范围继续检查 |

《财经法学》的校方官网和知网投审平台提供了内容相同的 Word 文件，适合验证附件去重和多来源记录。

以《中国软科学》为例，程序应保存官网的投稿须知网页，并从投稿格式页发现、下载《中国软科学》稿件模板。同时应发现同页的稿件审查表入口。页面将该表标注为录用后下载，按当前收录规则登记为待核验，直到有证据表明它也涉及稿件格式或提交文件要求。
